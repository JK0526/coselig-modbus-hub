## 安裝與設定

- [ ] 從 HACS custom repository 安裝指定 v1.0 revision；確認只有一套 custom component。
- [ ] 新增整合，第一頁只有 Host／Port，Port 預設 502。
- [ ] 錯誤 IP／Port 連不上：留在原頁、友善錯誤、修改後可重試、不留下半完成 Entry。
- [ ] 正確 IP：自動掃描 1～32；HA 原生 progress 與已找到設備數可見。
- [ ] 掃不到：重新掃描、修改範圍、取消都能正常使用。
- [ ] 自訂範圍 1～247 內；完成管理流程後再次進入保存的範圍一致。
- [ ] Scanner 列出的 Slave 與現場一致；型號由使用者指定，不猜 P404／P210。
- [ ] 新 P404 預設 single／single；P210 不出現 Group 設定。
- [ ] 完成後每 Slave 一個 Device，沒有額外 Gateway Device。
- [ ] 不需要 MQTT、Node-RED、YAML 或 Web Panel。

## P404 四種模式

以下在 A single／B single、A CCT／B single、A single／B CCT、A CCT／B CCT **分別執行並記錄**：

- [ ] Entity 數量、名稱、實體輸出與設定一致；沒有重複占用 register。
- [ ] 單路 ON／OFF。
- [ ] 單路 2%、25%、50%、75%、100% 各點正確，1% 不低於既有 2% 最低亮度。
- [ ] Group A single → CCT → single，只影響 CH1／CH2／CCT A。
- [ ] Group B single → CCT → single，只影響 CH3／CH4／CCT B。
- [ ] 未改的另一 Group 的 entity_id、unique_id、自訂名稱與自動化保持。
- [ ] 移除模式輸出的自動化參照已人工調整；不期待已刪除 registry 項目的名稱自動恢復。

## Slider 與 Optimistic

- [ ] 快速操作 `0 → 100 → 30 → 80`，UI 立即回應，不等待每筆 RS485 回覆。
- [ ] 快速 ON → OFF；最後設備為 OFF，沒有舊 ON 在後面執行。
- [ ] Bus 控制只執行已在途與最後 pending 值，沒有慢慢播放中間 slider 歷史。
- [ ] 最後正常 poll 與設備為 80%，HA 真實值一致。
- [ ] 模擬寫入 echo 遺失／損毀：不自動重送、不立即閃回舊值，之後 poll 校正。

## CCT

- [ ] 亮度／ON／OFF，對應實體輸出正確。
- [ ] 色溫最低、中央、最高及至少兩個中間點，核對 raw 0～100、冷暖方向、175～455 mired 映射。
- [ ] 快速同時變更亮度／色溫，最後狀態正確，沒有舊色溫覆蓋新操作。
- [ ] 確认第二個 register 是色溫值，而非另一個獨立實體輸出的錯誤寫入。
- [ ] 單路模式只調該路，不發色溫 request。

## P210

- [ ] CH1、CH2 各自測 ON／OFF 與 2%、25%、50%、75%、100%。
- [ ] 每 Slave 只讀 2 registers，不觸碰第三／第四路。
- [ ] 不存在 CCT／Group 欄位或色溫實體。

## 外部狀態與輪詢

- [ ] 使用外部實體操作改變設備值；約 poll interval＋bus round latency 內，HA 正常校正。
- [ ] 多設備或失聯造成整輪超過設定週期，queue 不持續成長，不累積多輪 poll。
- [ ] Write 能插在等待中的 poll 前，已在途 poll 自然完成。
- [ ] 重新掃描期間不穿插 poll／control；掃描結束與取消都恢復輪詢。

## 斷線與恢復

- [ ] Gateway 斷電：所有 Entity unavailable、HA 不 crash、不需要手動 reload、log 不洗版。
- [ ] Gateway 恢復：自動 reconnect，退避 1／2／4／8／15／30 秒，連線成功重置退避。
- [ ] reconnect 後完整 poll、逐設備恢復 available，不執行離線前堆積的舊控制。
- [ ] HA 啟動時 Gateway 離線，Entry 自動 retry；設備恢復後不需人工 reload。
- [ ] 單一 Slave 失聯：先前已讀成功者前兩次失敗保持 available，第三次 unavailable；其他設備正常。
- [ ] 單 Slave 成功後清失敗計數與恢復；CRC／wrong response 不直接判整個 Gateway offline。
- [ ] 所有 configured Slaves 一輪失敗，TCP 重建後能恢復。
- [ ] 關機／reload／卸載後沒有殘留 socket、worker 或 poll task。

## 管理、身份與診斷

- [ ] 新掃到 Slave 標示 New，只有勾選才加入。
- [ ] 未掃到舊 Slave 標示 Missing，預設保留，不自動刪；全部 Missing 時也相同。
- [ ] 明確取消勾選才刪除該 Slave Device／Entities。
- [ ] 修改 Host A → B，新 TCP 成功前舊設定不被修改；成功後 Entry ID、Device identifier、Entity unique_id 不變。
- [ ] HA 自訂名稱在 reload／重新掃描／修改 IP 後保持。
- [ ] Diagnostics 包含 queue depth／peak、成功／失敗、timeout／CRC／reconnect、availability／failure count 與 P404 groups。
- [ ] Diagnostics 不含明文 Host／IP、密碼、packet history 或其他 HA Device。
- [ ] HA 重啟／reload 後 runtime counters 歸零。

## 24～48 小時 Soak Test

- [ ] 至少連續 24 小時，建議 48 小時；期間包含一般操作、快速 slider、外部操作、單 Slave 失聯與 Gateway 電源循環。
- [ ] 記錄開始／結束時間、設備數、poll 週期、最長輪詢延遲。
- [ ] 定時保存 diagnostics（例如 0／1／6／12／24／48 小時），對照 request、timeout、CRC、reconnect、queue_peak。
- [ ] 觀察 task leak、socket leak、memory growth、queue growth；記錄 HA 系統監測方法與數值。
- [ ] 確認每輪開始不累積 task／timer；queue 在穩定運作時會歸零。
- [ ] 確認 warning 只在狀態變更／queue full，不每 2 秒洗版。
- [ ] 保留故障恢復與最終設備狀態證據。
