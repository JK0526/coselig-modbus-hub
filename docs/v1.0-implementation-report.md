## A. 架構

唯一產品核心為 `custom_components/coselig_modbus_hub/`。

| 模組 | 責任 |
| --- | --- |
| models | Device／Model／GroupMode、register 分配、身份、亮度／Kelvin |
| protocol | CRC16、0x03／0x06、例外回覆、完整 echo、TCP 拆包 |
| transport | 單一 socket／worker、單筆在途、優先序、合併、容量與統計 |
| scanner | 合法 Slave 探測、獨佔 bus、無型號猜測 |
| coordinator | HA listener、輪詢、真實 cache、availability、failure／reconnect |
| hub | Transport／Coordinator 啟停與暫停輪詢的掃描 |
| light | Native LightEntity、立即 optimistic 更新與 poll 校正 |
| config_flow | 原生 Config／Progress／Options／Reconfigure |
| __init__ | typed ConfigEntry[Hub].runtime_data、平台與 registry lifecycle |
| diagnostics | redacted runtime snapshot |

資料流：RS485 Device → RTU over TCP Gateway → Protocol／Transport → Coordinator cache → Native LightEntity → HA。Entity 不開 socket、不自行 poll。控制先更新 UI，再經 Coordinator 使用同一 Transport。

data 僅 Host／Port；options 僅 polling interval、最後完成的 scan range 與 devices。Runtime 狀態、counter、queue 深度與 Entity 名稱不持久化。

## C. Config Flow

schema **VERSION=2／MINOR_VERSION=1**。

1. Gateway 只顯示 Host／Port，預設 502。真正測 TCP，失敗保留輸入，可修改重試。
2. 自動掃描 1～32，原生 progress task 顯示進度與找到數。共同 probe 為 0x03／0x082A／count 2；完整驗證 slave／function／length／CRC。
3. 逐 Slave 選 P404／P210，預設 P404，無 model guessing。
4. 只對 P404 選兩組 single／CCT，預設 single／single；全部確認後才建立 Entry。

無設備提供重試、範圍、取消，不留半完成 Entry。取消會取消 scan task 與釋放資源。

Reconfigure 新 TCP 成功後才更新 data 與 reload，失敗保留原設定與身份。Options 使用 `OptionsFlowWithReload`；一般設定只有 poll interval（預設 2、最低 0.5），另有管理設備與自訂範圍掃描。

Existing／Missing 設定預設保留，New 勾選才加入，取消勾選才移除；全部 Missing 也不自動刪。掃描先暫停 Coordinator、等舊交易完成、獨佔 Transport，結束／失敗／取消後釋放鎖。

## D. Entity

| Profile | 原生燈光 |
| --- | --- |
| P404 single／single | CH1、CH2、CH3、CH4 |
| P404 CCT／single | 雙色溫 A、CH3、CH4 |
| P404 single／CCT | CH1、CH2、雙色溫 B |
| P404 CCT／CCT | 雙色溫 A、雙色溫 B |
| P210 | CH1、CH2，無 groups／CCT |

使用 has_entity_name、Brightness／ColorTemp color modes 與正式 Kelvin API。unique_id 為 `{entry_id}_slave_{slave}_chN`／`_group_a`／`_group_b`；Device identifier 為 Entry ID＋Slave，不含 IP、name、entity_id。

每 Slave 一個 Device，Manufacturer Coselig、Model P404／P210、名稱如 `Coselig P404 #03`，沒有 Gateway Device。

操作先 `async_write_ha_state()` 再送 Modbus，後續真實 poll 校正；操作前已開始的舊 poll 不覆蓋新 optimistic 值。寫入失敗不立刻回退，交由正常 poll 確認。

模式切換只刪目標 Group 不再適用的 Entity Registry 項目；另一 Group 的身份／名稱完整保留。被刪輸出的自動化與自訂 metadata 需人工處理，README 已明示。

## E. Queue／Poll

- 永遠一筆 in-flight，已執行交易不取消。
- Control 優先於 pending poll；實測順序 Poll 1 → Write → Poll 2 → Poll 3。
- 控制容量 32，key 含 Slave／邏輯輸出／命令類別；同類 pending latest-wins。
- 未開始 20／30／40／80 只送 80；20 已執行則送 20／80。
- CCT brightness／temperature 分開合併，在讓出執行權前依操作順序入列。回歸測試確認同 tick ON → OFF 及快速 CCT 不會舊操作蓋新操作。
- 滿佇列可合併仍更新；不可合併新指令明確拒絕＋warning，無 silent drop。
- Coordinator 每 Slave 一筆 read 並 await，P404 4／P210 2 registers，再分給 Entities。
- 週期按整輪開始計算；2 秒 target／3 秒 round 立即下一輪，無重疊 round／timer backlog。
- Write 只驗 echo，不 read-back、retry 或 replay。

## F. Failure handling

單 Slave timeout／CRC／非法回覆只累加該 Slave；先前已讀成功者 fail 1／2 available、fail 3 unavailable，成功清 counter。未首次確認的設備保持 unavailable。

TCP refused／reset／EOF 為 GatewayError，所有設備 unavailable，runtime 退避 1／2／4／8／15／30／30 秒。連線成功 reset，立即完整 poll，逐設備恢復真實狀態。整輪全部 Slave 失敗重建 TCP，不把單 Slave timeout 當全域離線。

首次 Gateway 離線使用 ConfigEntryNotReady，HA 自動 retry。離線／掃描時拒絕控制；bus failure 清除未執行控制，reconnect 不播放舊指令。

Gateway lost／Slave unavailable warning 只在狀態轉變；逐次 poll／scan 與寫入故障細節只使用 DEBUG。無 transient Repair。

Unload 先確認平台成功，失敗保留 runtime。HA shutdown 同樣停止 poll／worker、取消等待命令並關 socket。Diagnostics 統計為 runtime，Host 固定遮罩，不含密碼、其他設備或 packet history。
