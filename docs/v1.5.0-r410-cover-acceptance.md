# v1.5.0 R410 Cover Hardware Acceptance

Status: **PASS — real-device hardware acceptance confirmed by the project owner.** This record reflects the explicit acceptance supplied for v1.5.0 stable promotion. It records the confirmed behavior below without treating automated tests as hardware evidence.

## Confirmed behavior

- The integration creates a native Home Assistant `CoverEntity` for each configured R410 Cover.
- OPEN, CLOSE, and STOP use FC06 writes to register `0x019B`.
- Two-relay and three-relay modes work with arbitrary/free Relay mappings.
- The R410 hardware Momentary duration is configurable from 0.1 to 25.0 seconds.
- The entity is command-only: state and position remain unknown; the integration does not infer travel or position.
- Relays allocated to a Cover are not exposed as normal Switches. Unused Relays remain Switches, and deleting a Cover restores its Relay Switches.
- Cover actions use a non-coalescing FIFO. Existing stateful Light/Switch latest-wins behavior remains unchanged.
- Cover operation coexists with normal Poll traffic.
- Reload and entity-registry behavior were validated.
- Real R410 hardware acceptance: **PASS**.

## Safety boundary

R410 Cover is intended for dry-contact momentary inputs of an external curtain / rolling-door / garage-door controller.

It does **not** directly drive or reverse mains motor power and does **not** replace:

- electrical or direction interlocks;
- travel limits;
- overload protection;
- obstacle protection; or
- the external controller's safety logic.

The external controller must enforce motor direction, limits, and safety. Do not connect R410 relay outputs directly to mains motor direction wiring.

## Acceptance scope

PASS applies to the behaviors explicitly listed above. The supplied acceptance report did not include the controller model, Gateway/R410 firmware, dated logs, wiring diagrams, or a measured soak-test duration; this record does not invent those details or claim additional scenarios as hardware-tested.
