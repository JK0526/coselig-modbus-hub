## A. Two-relay default mapping

- [ ] Configure OPEN=R1, CLOSE=R2.
- [ ] OPEN activates the R1 momentary input.
- [ ] CLOSE activates the R2 momentary input.
- [ ] STOP triggers R1+R2 simultaneously.
- [ ] Confirm the external controller, rather than this integration, enforces motor safety and limits.

## B. Two-relay free mapping

- [ ] Configure OPEN=R4, CLOSE=R1.
- [ ] OPEN activates R4; CLOSE activates R1.
- [ ] STOP triggers R4+R1 simultaneously.
- [ ] Confirm non-consecutive mapping works.

## C. Three-relay free mapping

- [ ] Configure OPEN=R3, STOP=R1, CLOSE=R4.
- [ ] Verify each action triggers only its mapped relay.
- [ ] Confirm arbitrary relay order is accepted.

## D. Pulse duration

- [ ] At 0.5 seconds, measure/observe the R410 hardware momentary interval.
- [ ] At 1.0 seconds, measure/observe the R410 hardware momentary interval.
- [ ] Confirm the next Modbus control can proceed after the normal FC06 echo without waiting for the pulse interval to finish.

## E. Rapid commands and overlap behavior

For each sequence, verify every Home Assistant action produces a separate ordered momentary command:

- [ ] OPEN → STOP
- [ ] CLOSE → STOP
- [ ] OPEN → CLOSE
- [ ] OPEN → STOP → OPEN
- [ ] OPEN → OPEN → OPEN

Record the physical result when a second `0x019B` command arrives before the first Momentary interval expires: ____________________

Do not infer or encode undocumented behavior from this observation.

## F. Mixed Cover and normal Relay allocation

- [ ] Assign R1/R2 to one Cover.
- [ ] Verify R1/R2 are not usable as normal Switches while allocated.
- [ ] Verify R3/R4 remain normal Switches and operate correctly.

## G. Two Covers on one R410

- [ ] Assign Cover A to R1/R2 and Cover B to R3/R4.
- [ ] Verify both Cover entities command their own Relay resources.
- [ ] Verify no normal Relay Switch remains active while all four Relays are allocated.

## H. Normal polling coexistence

- [ ] With normal Poll enabled, run Cover commands while monitoring R410 and other configured Modbus devices.
- [ ] Confirm Cover does not add Poll traffic or disrupt existing P404/P210/R410 polling.

## I. Runtime Poll pause

- [ ] Pause background Poll from Monitor.
- [ ] Confirm Cover commands still work.
- [ ] Confirm S402 events and regular controls still work as expected.

## J. `poll_interval=0`

- [ ] Set the saved poll interval to 0 and let the startup health poll complete.
- [ ] Confirm Cover commands remain available after that initial health confirmation.

## K. Reload

- [ ] Reload the integration with one or more configured Covers.
- [ ] Confirm each Cover retains its unique identity and no duplicate Cover appears.
- [ ] Confirm the configured Relay allocation is restored and unused Relays return as Switches.
- [ ] Confirm Cover position and open/closed/moving state remain unknown.

## L. Remove Cover

- [ ] Remove a Cover and confirm the configured Relay Switch entities return.
- [ ] Confirm the original Relay unique IDs, entity IDs, custom names, and Areas are retained where Home Assistant supports them.
- [ ] Confirm the removed Cover entity is removed and a later new Cover receives a new identity.

## M. Gateway loss and reconnect

- [ ] Disconnect the Gateway and confirm Cover availability follows Gateway/R410 health.
- [ ] Restore the Gateway and confirm availability recovers through the existing integration reconnect path.
- [ ] Confirm an uncertain timed-out write is not automatically replayed.

## N. Long mixed-use coexistence

- [ ] Run Cover commands alongside P404, P210, ordinary R410 Switches, and S402 events for a representative extended period.
- [ ] Confirm normal polling, control, event reception, and reconnect remain healthy.
