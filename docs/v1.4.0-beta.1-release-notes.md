# Coselig Modbus Hub v1.4.0-beta.1

**Beta / Hardware validation build**

**Hardware acceptance pending.** This release is for S402 hardware acceptance; it is not the stable v1.4.0 release. The previous stable baseline remains v1.3.3.

## What's included

- S402 DI 4x asynchronous input support for four single-click `PRESS_END` events.
- A Continuous RX Dispatcher that routes unsolicited S402 frames alongside existing Modbus request/response traffic.
- Four native Home Assistant EventEntity instances per configured S402.
- Standalone `EVENT` traces in Modbus Monitor, including S402 ID, DI, event type, and configured status.
- S402-only Gateway setup without requiring a Modbus scan.
- Modbus Slave #1 reservation while any S402 is configured. Existing legacy Slave #1 entries remain intact and prevent adding S402 until removed.
- S402 IDs use their own 0–255 namespace; for example, S402 #51 and Modbus Slave #51 may coexist.
- Config Entry schema remains 2.1; existing entries without `s402_devices` load with an empty S402 list.
- S402 events require **zero additional Modbus requests** and do not increment Modbus request statistics.
- P404, P210, and R410 polling and control behavior is intended to remain unchanged.

## Automated validation and hardware status

Automated validation passed: **512 Python tests**, **38 frontend tests**, **99.95% branch coverage**, and **100% Config Flow line / branch coverage**. Ruff lint and format checks, lockfile validation, and JSON validation also passed.

Hardware acceptance is still pending. In particular, **S402 and existing Poll / Control coexistence still requires real hardware validation**. Do not treat automated tests as proof of bus-level coexistence or publish this beta as a stable release.

Use the [S402 hardware acceptance checklist](v1.4.0-s402-acceptance.md) to record results. The formal stable `v1.4.0` release will be considered only after that acceptance is completed and confirmed.
