# Coselig Modbus Hub v1.5.0

**Stable release.** R410 Cover hardware acceptance and the device-oriented Options Flow have both been validated on the project owner's Home Assistant installation. See the [R410 Cover hardware acceptance report](v1.5.0-r410-cover-acceptance.md) for the confirmed hardware scope and safety boundary.

## R410 Cover

- Adds a native Home Assistant `CoverEntity` for R410 momentary relay control.
- Sends FC06 Momentary commands to register `0x019B` for OPEN, CLOSE, and STOP.
- Supports two-relay and three-relay configuration with arbitrary/free Relay mapping.
- Configures hardware Momentary duration from 0.1 to 25.0 seconds.
- Keeps the Cover command-only: state and position remain unknown.
- Allocates used Relays to the Cover and exposes unused Relays as normal Switches; deleting a Cover restores its Relay Switches.
- Queues Cover actions in a non-coalescing FIFO. Existing stateful Light/Switch latest-wins behavior is unchanged.
- R410 Cover hardware acceptance: **PASS**.

R410 Cover is intended for dry-contact momentary inputs of an external curtain, rolling-door, or garage-door controller. It does not directly drive or reverse mains motor power and does not replace interlocks, limits, overload protection, obstacle protection, or the external controller's safety logic.

## Device-oriented management UX

- Separates Options into **Device management** and **Communication settings**.
- Separates **Add device** from **Manage installed devices** and provides one selector for P404, P210, R410, and S402.
- Places P404/P210 output-mode changes and device removal under the selected device.
- Places R410 output configuration and Cover management under the selected R410.
- Places S402 management under the selected S402.
- Keeps background polling interval and Slave scan range in Communication settings. Gateway Host/Port remains in Home Assistant's native Reconfigure flow.
- Back and cancel navigation does not save partial changes.
- Real Home Assistant Options Flow validation: **PASS**, including the translation and FormatJS fixes described below.

## Fixes

- Removes the unresolved `{devices}` placeholder from the installed-device selector and provides a separate empty-device step.
- Eliminates FormatJS `MISSING_VALUE` errors caused by dynamic Options Flow titles. Titles are static; device, Slave, and model context appears in descriptions.

## Compatibility

- Config Entry schema remains **2.1**; no migration is required.
- Existing P404, P210, R410, and S402 configurations remain compatible.
- Existing R410 Cover configurations remain compatible.
- The persisted Options format is unchanged: `devices`, `s402_devices`, `r410_covers`, `poll_interval`, `scan_start`, `scan_end`, and unknown/future options are preserved.
- Modbus protocol behavior and transport/runtime architecture are unchanged by this stable promotion.
