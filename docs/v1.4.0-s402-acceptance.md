# v1.4.0 S402 Hardware Acceptance

Status: **PASS — accepted for the v1.4.0 stable release.** This record reflects the project owner's explicit report of real-device results from the `v1.4.0-beta.2` build. The report did not include setup details, dated logs, or raw diagnostics, so this document records the confirmed outcomes without inventing those details. Automated regression results are tracked separately and are not treated as hardware evidence.

## Real hardware results reported as PASS

- S402 DI1, DI2, DI3, and DI4 EventEntity behavior.
- Single-click events use `PRESS_END`.
- The Monitor displays S402 EVENT traces as standalone events.
- Rapid, repeated high-frequency S402 event stress produced no missed events.
- Continuous RX coexists with normal Modbus Poll and Control; high-frequency events did not disrupt either.
- Multiple S402 devices have distinguishable parent names, and their EventEntities appear under the correct parent devices.
- Integration reload does not create duplicate S402 events or entities.
- Runtime Poll pause works; S402 EVENT and Control continue while paused.
- Poll resume works without a backlog; the configured `poll_interval` remains unchanged.
- Integration reload clears the runtime Poll pause.

## Not reported as hardware-tested

The following acceptance checklist cases were not included in the supplied hardware results and are not claimed as PASS here:

- S402-only Gateway setup and setup without starting a Modbus scan.
- Unknown S402 IDs, invalid CRC/DI frames, and truncated frames.
- Gateway disconnect/reconnect and EventEntity availability across reconnect.
- Ordinary Modbus Slave #1 reservation conflicts, scanner conflict handling, and same-number S402/Modbus coexistence.
- Direct verification that an event generates zero Modbus requests, and the precise `TX → EVENT → RX → OK` pending-response case.
- Polling disabled by setting `poll_interval = 0`, Monitor event filtering/counter behavior, and a 24-hour (or longer) soak test.
- Physical Gateway unplug/reset behavior and P404/P210/R410 operation on the same hardware topology.

These unreported cases do not change the release decision recorded below. They remain unverified by the supplied real-device report; automated regression coverage remains useful but does not replace them.

## Automated regression validation

The stable promotion reruns the full Python and frontend suites plus lint, format, lockfile, JSON, and diff checks. Their final results are recorded in the v1.4.0 release commit and release report; they are separate from the real-device results above.

## Acceptance decision

- Hardware result: **PASS for the reported scenarios above**.
- Release acceptance: **Approved for v1.4.0 stable promotion by the project owner**.
- Hardware scenarios not reported above: **Not claimed as verified**.
