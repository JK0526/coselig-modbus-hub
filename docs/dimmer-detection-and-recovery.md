# 調光器辨識與通訊恢復

## Scanner 的型號推薦

Scanner 先以 FC03 讀取共用識別暫存器 `0x0000`。探測到 Slave 後，再依序測試 `0x082A` 的可讀範圍。兩種調光器保留手動選項。高可信度推薦會預選，低可信度只提供提示，使用者需明確選擇。

| 探測結果 | 推薦 | 可信度 |
| --- | --- | --- |
| 第一次讀取 4 個暫存器成功 | P404 | 高 |
| 讀取 4 個時收到 CRC 正確的 Modbus Exception `0x02` 或 `0x03`，讀 2 個成功 | P210 | 高 |
| 兩次讀 4 個都回傳特徵性 FC83/03 壞 CRC，而且各自接續讀 2 個成功 | P210 | 高 |
| 讀 4 個逾時、出現單次 CRC 錯誤或其他協定錯誤，讀 2 個成功 | P210 | 低 |
| 首次出現特徵性 CRC 錯誤，但重試讀 4 個成功 | P404 | 低 |
| 兩種讀取都失敗 | 由 R410 功能探測判定，否則型號未知 | — |
| TCP 失敗 | 掃描回報 Gateway 失敗 | — |

現場樣本 `3E 83 03 00 3D` 未通過 CRC。其資料的正確 CRC 尾碼為 `31 3D`。配對的 2 暫存器回覆 `3E 03 04 00 00 00 00 35 30` 可通過檢查。Scanner 只比對同一 Slave 回覆的完整特徵，且要求重現。此特徵仍需用不同設備及韌體確認，其他壞 CRC 不會被當成這個特徵。

## 修正已安裝的型號

在「管理已安裝裝置」選擇調光器，按「修正型號」，確認摘要後 Home Assistant 會重新載入整合。初次輪詢會使用新型號的範圍，失敗次數與退避從新 runtime 重新計算。單純掃描只讀取探測資料。

同一 Slave 的父裝置與 A 組保留 Unique ID，並保留原本的輸出模式。P404 改為 P210 會移除 B 組的設備及實體登錄，引用它們的自動化需要調整。P210 改為 P404 時，新增的 B 組預設為兩路獨立調光，可再修改輸出模式。

## 背景輪詢與串流恢復

- 各 Slave 連續三次輪詢失敗後標記不可用，背景排程依序在至少 30、60、120、240、300 秒後的下一輪重新探測。成功後清除該 Slave 的退避。明確要求的手動讀取仍可立即檢查。背景輪詢不變更設定型號。
- CRC 正確且屬於當前請求的 Modbus 例外，或已驗證的暫存器值域錯誤，只影響該 Slave。CRC 錯誤、破損封包、回覆不匹配和交易逾時仍隔離舊串流，避免誤用遲到回覆。
- 所有建連經過 Transport 的同一個連線鎖和重連時限。串流清理或建連失敗後至少等待 100 毫秒才再嘗試，Gateway 故障仍由背景排程採用原有的遞增退避。其他 Slave 保留原輪詢間隔設定，必要的串流重建可短暫延長當輪。軟重置期間保留健康實體的狀態，暫停接受控制，直到 TCP 重建。
- EOF、連線重設或重新建連失敗仍會標示 Gateway 離線。在一筆輪詢交易中失去 TCP 時，下一輪從後一個 Slave 開始。反覆中斷的 Slave 進入獨立退避，多 Slave 首輪遇到這種中斷也可保留 runtime，讓後面的設備有機會輪詢。
- 已送出的控制不會因為重連而重送。100 毫秒是連線重建間隔，透明 Gateway 是否會把遲到的串列回覆送到新 TCP 仍需實機確認。
