# Coselig Modbus Hub v1.6.4

修復 TCP Gateway 暫時斷線後的自動恢復，以及 P404／P210 輪詢失敗對連線的影響。

- 整輪 Slave 輪詢失敗不再額外關閉 TCP。有效的 Modbus 例外回覆及暫存器值域錯誤只計入 Slave 健康狀態；各 Slave 保留連續三次失敗門檻。
- 交易逾時或封包驗證失敗需要隔離舊串流時，Transport 通知排程重建 TCP。背景輪詢停用或暫停時仍會重連，不會因此增加 FC03。
- 有啟用輪詢且有可輪詢設備時，重連後收到至少一筆有效輪詢才重設退避。停輪詢及僅事件設備則以 TCP 重連成功為準。
- HA 設定項目重試訊息區分初次 TCP 建連失敗與首次輪詢期間失去 Gateway。單一 Slave 的交易逾時仍由輪詢健康狀態處理。
- 控制寫入不會自動重送。設定項目 schema 維持 2.1，更新時可保留原整合及實體。

## HACS 更新與 HA 驗證

1. 在 HACS 檢查 Coselig Modbus Hub 更新，選擇 v1.6.4，安裝後重啟 Home Assistant。
2. 確認原整合載入，P404／P210 可讀取狀態及控制，既有 R410／S402 功能正常。
3. 在維護時段暫時中斷 Gateway 網路再恢復。確認同一個整合自動重連，輪詢及控制恢復。
4. 若使用停用或暫停輪詢，確認 TCP 仍會重連，Monitor 不出現由重連觸發的背景 FC03。
